# Диаграмма бизнес-процесса (BPMN)

## Описание процесса

Процесс описывает основной бизнес-процесс добавления операции с проверкой пропускной способности и отправкой уведомлений при перегрузке.

## Визуальное представление

```

│                                                                 │

│  │  Начало  │─────▶│ Проверка пропускной  │─────▶│ Шлюз     │  │
│  │ Добавл.  │      │    способности       │      │Перегруз? │  │
```

## Элементы процесса

### Стартовое событие
- **ID**: StartEvent_1
- **Название**: Добавление операции
- **Описание**: Инициирует процесс при добавлении новой операции

### Задача 1
- **ID**: Activity_1
- **Название**: Проверка пропускной способности
- **Описание**: Проверяет текущую пропускную способность системы

### Шлюз (Gateway)
- **ID**: Gateway_1
- **Название**: Перегрузка?
- **Тип**: Exclusive Gateway (исключающий шлюз)
- **Описание**: Принимает решение на основе результата проверки пропускной способности

### Задача 2
- **ID**: Activity_2
- **Название**: Отправка уведомления
- **Описание**: Отправляет уведомление при обнаружении перегрузки

### Конечное событие
- **ID**: EndEvent_1
- **Название**: Завершение
- **Описание**: Завершает процесс

## Потоки последовательности

| ID потока | Источник | Цель | Описание |
|-----------|----------|------|---------|
| Flow_1 | StartEvent_1 | Activity_1 | Переход от начала к проверке |
| Flow_2 | Activity_1 | Gateway_1 | Переход от проверки к шлюзу |
| Flow_3 | Gateway_1 | Activity_2 | Путь при перегрузке (да) |
| Flow_4 | Gateway_1 | EndEvent_1 | Путь при отсутствии перегрузки (нет) |

## Исправления в BPMN файле

### Проблема
Flow_4 имел неправильные координаты waypoint, что приводило к некорректному отображению линии перехода от шлюза к конечному событию.

### Решение
Обновлены координаты waypoint для Flow_4:
- **Было**: `<di:waypoint x="425" y="155" />` → `<di:waypoint x="650" y="155" />`
- **Стало**: `<di:waypoint x="425" y="155" />` → `<di:waypoint x="668" y="120" />`

Это обеспечивает правильное отображение линии, которая теперь корректно соединяет шлюз с конечным событием.

## Логика процесса

1. **Запуск**: Процесс начинается с события "Добавление операции"
2. **Проверка**: Система проверяет пропускную способность
3. **Решение**: На основе результата проверки:
   - **Если перегрузка (да)**: Отправляется уведомление → Завершение
   - **Если нет перегрузки (нет)**: Прямой переход к завершению
4. **Завершение**: Процесс завершается
